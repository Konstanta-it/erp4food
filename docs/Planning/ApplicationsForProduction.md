# Обеспечение заявок на производство

АРМ **"Обеспечение заявок на производство"** включает функционал разузлования потребности по заявкам на производство, формирования производственных заданий и заказов на перемещение. Он расположен в разделе  **"Обеспечение заявок на производство"** в подсистеме **"Планирование"**.

[![1][1]][1]

Для заполнения настроек АРМа используются ["Настройки обеспечения заявок на производство"](Settings/ApplicationsForProduction.md).

[![2][2]][2]

---

На вкладке **"Потребность по заявкам"** при нажатии на кнопку *"Обновить"* выводится потребность из документа **"Заявка на производство"**, распределенная по [рабочими центрами](../CommonInformation/WorkCenter.md).

[![3][3]][3]

Заявки подбираются по дате планирования (соответствует дате задания из заявки), настройке формирования, виду заявки, этапу для чтения и отборам из указанных в АРМе настроек.

Количество продукции из заявок автоматически распределяется в равных долях между всеми [рабочими центрами](../CommonInformation/WorkCenter.md), на которых выпускается продукция. Если для продукции подобран один [рабочий центр](../CommonInformation/WorkCenter.md), то количество недоступно для редактирования; в других случаях есть возможность отредактировать полученное количество вручную.

---

На вкладке **"Запуск в производство"** при нажатии на кнопку *"Обновить"* происходит разузлование потребности из заявок по всем этапам производственной цепочки - от конечной продукции до сырья.

[![4][4]][4]

Данные в строках верхнего уровня заполняются в соответствии с заявленной потребностью, а последующие строки дерева формируются в процессе разузлования по данным из основных спецификаций. В системе разузлование доступно для продукции с типом *"Полуфабрикат"* и *"Базовый продукт"*, а также для *немаркированной* готовой продукции (в характеристике указан флаг *"Немаркированная продукция"*). 

Если в этапе спецификации указано несколько [рабочих центров](../CommonInformation/WorkCenter.md), то в дереве будут отражены данные по всем [рабочим центрам](../CommonInformation/WorkCenter.md). Склад выпуска заполняется из рабочего центра.

Количество в колонке *"Потребность"* рассчитывается исходя из коэффициента выхода по спецификации и распределяется в равных долях между [рабочими центрами](../CommonInformation/WorkCenter.md).

Кратность партии для данных верхнего уровня будет заполнена согласно данным из заявки на производство, а для строк, разузлованных по спецификациям, получается из настроек партии запуска.

В колонке *"Партионная потребность"* количество заполняется согласно потребности в производстве, округлённой вверх по кратности партии. Например, если количество потребности равно 80, а кратность в спецификации заполнена и равна 50, то партионная потребность будет равна 100. Если кратность партии не указана, то партионная потребность будет равна потребности.

Дата маркировки доступна для заполнения, если она не была указана в заявке на производство. Дата смены заполняется автоматически согласно дате планирования, но для производимой продукции её можно изменить вручную.

По кнопке *"Обеспечить"* рассчитывается **количество к производству**, исходя из потребности и количества остатка, которым можно обеспечить эту потребность.

[![5][5]][5]

В процессе обеспечения для каждой строки дерева производства происходит автоматический расчёт остатка, доступного для обеспечения потребности (частично или полностью). При этом доступный для обеспечения остаток динамически уменьшается, если он уже был использован для обеспечения в строках выше. Итоговое количество к производству по строке будет рассчитано исходя из потребности и обеспечения этой потребности остатком.

При необходимости можно скорректировать количество к производству. Необходимо вносить изменения, начиная с верхнего уровня дерева (например, готовой продукции), последовательно спускаясь к сырью. Если при корректировке количества к производству в какой‑либо строке использовался остаток, то автоматически пересчитаются все нижестоящие строки с учётом обновлённого значения доступного остатка.

По кнопке *"Сохранить"* происходит формирование производственных заданий согласно данным запуска в производство.

[![6][6]][6]

Производственные задания сохраняются согласно настройке *"Объединять запуск в производственных заданиях"*. Если флаг установлен, то производственные задания будут формироваться в разрезе [рабочих центров](../CommonInformation/WorkCenter.md) с суммированием количества одинаковой продукции. Основанием корневого производственного задания будет заявка на производство, все последующие задания сформируются на основании корневого задания. Если флаг не установлен, то для каждой производственной цепочки (от готовой продукции/полуфабриката/базового продукта до сырья) сформируются отдельные производственные задания без объединения количества одинаковой продукции. Основанием корневого производственного задания будет заявка на производство, все последующие задания сформируются на основании предыдущих, отражая цепочку зависимых документов.

Если в процессе разузлования возникли ошибки и они отражены на вкладке **"Ошибки НСИ"**, то при сохранении будет выведено сообщение с вопросом о сохранении документов.

---

На вкладке **"Ошибки НСИ"** выводятся ошибки, полученные в результате разузлования потребности по заявкам. Ошибки показывают отсутствие спецификации для номенклатуры, рабочего центра в этапе производства, склада выпуска в рабочем центре.

[![7][7]][7]

---

На вкладке **"Формирование перемещений"** по кнопке *"Обновить"* происходит расчёт потребности к перемещению со склада на склад. Необходимость обеспечения между складами определяется настройкой *"Требуется обеспечение по складам"* в рабочем центре. Если признак не установлен, то производственные задания по этому рабочему центру не будут участвовать в формировании [заказов на перемещение](../Warehouse/MovingProducts/TransferOrder.md).

[![8][8]][8]

Склад-получатель заполняется согласно складам основных и вспомогательных материалов из рабочего центра. Если склад основных материалов один и совпадает со складом вспомогательных материалов, то склад-получатель заполнится автоматически. При наличии нескольких складов необходимо выбрать склад вручную из доступных вариантов в списке.

[![9][9]][9]

Склад-отправитель будет выбран из склада выпуска, указанного в карточке номенклатуры.

Дата перемещения автоматически устанавливается равной дате смены из производственного задания. При необходимости её можно изменить вручную.

По кнопке *"Обеспечить - С учетом остатка"*, исходя из потребности и количества остатка, которым можно обеспечить эту потребность,  рассчитывается **количество к перемещению**. 

[![10][10]][10]

При обеспечении происходит автоматический расчёт остатка, который может частично или полностью покрыть потребность к перемещению. При этом доступный для обеспечения остаток динамически уменьшается, если он уже был использован для обеспечения в строках выше.

По кнопке *"Обеспечить - Без учета остатка"* количество в колонке *"К перемещению"* заполняется согласно потребности 1 к 1, без учёта остатка.

[![11][11]][11]

Количество к перемещению доступно для редактирования. При внесении изменений в текущей строке остаток пересчитывается, а данные по обеспечению и количеству к перемещению в последующих строках, относящихся к той же продукции и складу, актуализируются.

По кнопке *"Сохранить"* происходит формирование заказов на перемещение на основании производственных заданий.

[![12][12]][12]

Строки с продукцией, по которой введено *"Разрешение на замену материалов"* и доступен выбор аналога, выделены восклицательным знаком. При изменении продукции на аналог количество в колонке *"Потребность"* пересчитается по коэффициенту замены.

[![13][13]][13]

**Восстановление контекста**

Функционал восстановления контекста в АРМе предназначен для следующих сценариев:

- раздельное формирование производственных заданий и заказов на перемещение;

- формирование новых заявок на производство (дозаказ) в ходе текущих производственных процессов с последующим обеспечением в АРМе.

В этом случае работа АРМа будет отличаться следующим образом:

На вкладке **"Потребность по заявкам"** при нажатии на кнопку *"Обновить"* будет выведена потребность из документа **"Заявка на производство"** вне зависимости от наличия производственного задания. Однако заявки на производство, по которым уже создано производственное задание, блокируются для редактирования (такие строки выделены серым цветом).

[![14][14]][14]

На вкладке **"Запуск в производство"** при нажатии на кнопку *"Обновить"* данные по заблокированным строкам потребности не восстанавливаются, разузлование происходит только для потребности из заявок без производственных заданий.

[![15][15]][15]

На вкладке **"Формирование перемещений"** при нажатии на кнопку *"Обновить"* будет выведена потребность к перемещению по всем производственным заданиям (и по тем, что относятся к "заблокированным" заявкам, и по созданным производственным заданиям для новых заявок). Однако, если по какой‑либо потребности уже был создан заказ на перемещение, строка будет заблокирована для редактирования (выделена серым цветом).
